# Integrate Skills Specification

**Scope**: Large

**Grilling Record**: [`.specs/decisions/grill-in-spec-driven.md`](../../decisions/grill-in-spec-driven.md)

**Spec Reviews**: [`spec-review-1.md`](spec-review-1.md), [`spec-review-2.md`](spec-review-2.md) (Dispositions recorded; changes applied in place)

## Problem Statement

Planning a feature takes two skills that overlap and disagree. `/grill-with-docs` gets the most complete requirements but writes no spec. spec-driven owns the spec, gates and reviewers, but its own questioning is shallower. They also keep two decision logs (ADRs and `STATE.md` `AD-NNN`), which models fill with one-paragraph entries. Several vendored skills still route work around spec-driven, and `grilling` is missing from opencode at work. Merge the specification phase into one grill inside spec-driven. Record every grilling session completely. Give spec-driven day-sized Tickets for the product team, keep working with plans written under older rules or outside spec-driven, and make spec-driven the only implementation path.

## User Stories

### P1: One grill inside Specify ⭐ MVP

**User Story**: As a developer planning a feature, I want spec-driven's Specify to grill me one question at a time, so that I get grill-with-docs-quality requirements straight into a reviewed spec.

**Why P1**: This is the merge the user asked for.

**Acceptance Criteria**:

1. **GRILL-01**: WHILE Specify is gathering requirements, the agent SHALL ask exactly one question per turn, each with concrete options and one recommended answer.

   ```gherkin
   Scenario: GRILL-01.S1 one question per turn
     Given a repository with spec-driven installed
     And the user asks to specify "add CSV export to the orders page"
     When the agent grills the user until shared understanding
     Then every agent turn contains exactly one question
     And every question lists its options and marks one as recommended
   ```

   **Proof**: inspect

2. **GRILL-02**: WHEN the user answers a question with "you decide" THEN the agent SHALL record its recommended option as that question's Decision with `Decided by: agent`.

   ```gherkin
   Scenario: GRILL-02.S1 you decide
     Given Specify asks "Which delimiter does the export use?" with "comma" recommended
     When the user replies "you decide"
     Then the Grilling Record holds a Decision choosing "comma"
     And that Decision reads "Decided by: agent"
   ```

   **Proof**: inspect

3. **GRILL-03**: WHEN the user answers "decide the rest" THEN the agent SHALL list its default for every remaining branch in one turn and wait for overrides.

   ```gherkin
   Scenario: GRILL-03.S1 decide the rest
     Given Specify has three unasked branches left: file name, encoding, column order
     When the user replies "decide the rest"
     Then the next agent turn lists one default for each of file name, encoding and column order
     And the agent writes nothing to spec.md until the user replies
   ```

   **Proof**: inspect

4. **GRILL-04**: WHEN Specify starts THEN the agent SHALL run the graphify capability search and report any Redundant Feature before its first question.

   ```gherkin
   Scenario: GRILL-04.S1 redundant feature first
     Given a repository whose src/export/csv.py already exports orders to CSV
     When the user starts Specify for "add CSV export to the orders page"
     Then the agent's first message names src/export/csv.py as an existing capability
     And it asks what the user needs beyond it before any other question
   ```

   **Proof**: inspect

5. **GRILL-05**: IF a native spec has no `## Decisions & Assumptions` section THEN `validate_spec.py` SHALL exit 1 and name that section, at every scope.

   ```gherkin
   Scenario: GRILL-05.S1 small spec without the section
     Given a Small-scope spec.md with a Grilling Record line and every Small section except "Decisions & Assumptions"
     When validate_spec.py runs on it
     Then it exits 1
     And its output names "Decisions & Assumptions"
   ```

   **Proof**: test

   ```gherkin
   Scenario: GRILL-05.S2 large spec with the old heading
     Given a Large-scope spec.md with a Grilling Record line whose assumptions section is titled "Assumptions & Open Questions"
     When validate_spec.py runs on it
     Then it exits 1
     And its output names "Decisions & Assumptions"
   ```

   **Proof**: test

6. **GRILL-06**: WHEN a spec's `## Decisions & Assumptions` section contains only `none` THEN `validate_spec.py` SHALL accept that section.

   ```gherkin
   Scenario: GRILL-06.S1 none is allowed
     Given a valid Small-scope spec.md with a Grilling Record line whose "Decisions & Assumptions" section reads "none"
     When validate_spec.py runs on it
     Then it exits 0
   ```

   **Proof**: test

7. **GRILL-07**: The spec-driven flow SHALL NOT write a per-feature `context.md`.

   ```gherkin
   Scenario: GRILL-07.S1 gray areas land in the spec
     Given a Specify session for "add CSV export" in which the user chose "download, not email"
   ```
